# Python 代码审查技能

## 执行目标
严格遵循 PEP8 规范，兼顾类型安全与可读性，检测代码中的隐患和优化空间，输出结构化审查报告。

## 执行步骤
1. 使用 read_file 工具读取待审查的 Python 文件
2. 逐项检查：
   - **PEP8 规范**：命名风格（snake_case / PascalCase）、缩进（4空格）、行宽（≤120字符）、空行、import 排序
   - **类型注解**：函数签名是否有类型注解、是否使用了 Any 宽类型
   - **潜在 Bug**：未处理的异常、可变默认参数、资源未关闭、循环引用
   - **可读性**：函数复杂度、魔法数字、注释是否解释 WHY 而非 WHAT
3. 使用 search_text 工具检查项目中是否有类似模式的代码可一并优化
4. 给出具体修改建议和修改后的代码片段（使用 replace_text / write_file 工具实施）

## 输出要求
审查报告使用 Markdown 格式，包含以下部分：
- **问题总览**：按严重程度（高危/中危/低危）分类统计
- **详细问题列表**：每个问题包含位置（文件名:行号）、违规类型、当前代码、建议修改
- **优化建议**：整体代码质量评分（A-F）和改进方向

## 注意事项
- 不要对测试文件（test_*.py、*_test.py）提出命名规范告警
- 第三方库的导入风格问题降低优先级
- 如果文件超过 300 行，优先关注架构拆分建议
