# 终端 UI 设计说明

本文档说明当前语音 Agent 的终端界面约定。目标是接近 Claude Code / Codex CLI 的使用感：信息密度高、状态弱化、输出稳定、不用大段提示打断对话。

## 目标

- 对话主线只保留用户输入和 AI 输出，减少重复回显。
- 等待、工具调用、朗读状态使用灰色弱提示，不抢主内容。
- 模型未返回前显示轻量动画，让用户知道程序仍在工作。
- 默认使用普通终端内联 UI：标题方框和对话内容都留在终端历史里，不接管全屏缓冲区。
- AI 回复按模型返回文本流式输出，当前行实时预览，完整行边界做轻量 Markdown 渲染，不额外接管滚动区。
- 输出刷新集中到 UI 模块，避免多个线程同时 `print` 导致错行。
- 不新增第三方依赖，保持课程环境直接运行。

## 交互约定

启动后会在当前终端缓冲区输出配置面板，然后进入普通输入循环：

```text
┌────────────────────────────────────────┐
│ AI 语音 Agent                          │
│ thinking: 已启用，推理强度：max         │
│ config: D:\...\config.json             │
│ 输入栏 Ctrl+C 两次或关闭窗口结束会话    │
└────────────────────────────────────────┘

> 石狮市的天气怎么样
- deepseek-v4-flash

^ 天气查询思路
  - 抱歉，我无法实时查询天气信息...
```

含义：

- 顶部方框使用灰色边框和淡蓝色文字显示思考模式和配置文件，模型名显示在输入行下方的暗黄色弱状态行。
- `>` 表示用户输入，显示为普通终端文本。
- `^` 表示 AI 回复，显示为普通终端文本。
- `!` 表示系统消息或错误。
- `·` 表示 Agent 工具状态。
- 对话与对话之间保留一行间隔。
- 等待、工具调用、朗读和错误状态用灰色弱提示显示在当前行或单独一行。
- 等待模型返回时，当前行会显示随机颜文字和跳动省略号，例如：

```text
AI 正在思考  (｡･ω･｡)...
```

Agent 工具调用属于次级状态，显示在消息区：

```text
· Agent 第 1 步请求工具：read_file
· 执行记录
  |
  —成功
```

## 技术方案

当前实现使用标准终端能力，而不是 GUI 或真正的字体控制：

- ANSI SGR：灰色、弱显示、重置样式。
- ANSI 光标控制：只用于当前行等待动画和输入行重绘。
- Unicode 字符：前缀、颜文字、状态文本。
- 后台线程：模型请求阻塞期间刷新等待动画。
- 输出锁：所有动态状态行通过同一个渲染器写入，降低错行概率。
- 轻量 Markdown 渲染：当前行用 ANSI 重绘做实时预览，完整行边界处理标题、列表、引用、代码块、管道表格、加粗、行内代码和链接。
- `msvcrt`：Windows 下读取单字符输入，用于斜杠命令补全和朗读期间打断。

程序会尝试在 Windows 控制台中开启 Virtual Terminal Processing；不支持 ANSI 时会退化为无颜色输出。

## 文件边界

- `ai_voice_agent/terminal_ui.py`：终端样式、ANSI 能力检测、启动面板、状态行、等待动画。
- `main.py`：业务主流程、语音输入、语音播报、Agent 调用。
- `docs/TERMINAL_UI.md`：本文档，记录交互约定和后续演进方向。

`main.py` 不再直接维护 ANSI 常量和等待动画细节，避免显示逻辑继续散落。

## 限制

- 终端无法真正设置“小字体”，只能使用灰色弱显示模拟次级信息。
- 执行中按 `Ctrl+C` 会取消当前操作并回到输入栏；输入栏连续两次 `Ctrl+C` 才退出程序。
- 标准库 `input()` 不支持 Claude Code 那种多行编辑、历史补全和快捷键体系。
- 当前内联 UI 不做完整 Markdown 渲染；嵌套块、复杂 HTML 等仍按近似文本展示。

## 后续升级

如果要继续向 Claude Code / Codex CLI 靠近，可以分两步：

1. 引入 `rich`：更完整的 Markdown、表格、进度和宽字符处理。
2. 引入 `prompt_toolkit`：更强的输入编辑、历史记录、快捷键、底部状态栏。

这两个依赖会改变安装要求，正式引入前需要先确认。
