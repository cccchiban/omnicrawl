# 终端 UI 设计说明

本文档说明当前语音 Agent 的终端界面约定。目标是接近 Claude Code / Codex CLI 的使用感：信息密度高、状态弱化、输出稳定、不用大段提示打断对话。

## 目标

- 对话主线只保留用户输入和 AI 输出，减少重复回显。
- 等待、工具调用、朗读状态使用灰色弱提示，不抢主内容。
- 模型未返回前显示轻量动画，让用户知道程序仍在工作。
- 默认进入全屏 TUI：消息区、状态栏和输入栏固定布局；标题方框作为第一条对话内容参与滚动。
- AI 回复按终端友好的 Markdown 子集渲染，支持标题、列表、引用、代码块、链接和常见强调。
- 输出刷新集中到 UI 模块，避免多个线程同时 `print` 导致错行。
- 不新增第三方依赖，保持课程环境直接运行。

## 交互约定

支持全屏 TUI 的终端会进入 alternate screen，布局如下：

```text
┌────────────────────────────────────────┐
│ AI 语音 Agent  model=deepseek-v4-flash  thinking=disabled │
│ config: D:\...\config.json              │
└────────────────────────────────────────┘

* 石狮市的天气怎么样

^ 天气查询思路
  - 抱歉，我无法实时查询天气信息...

────────────────────────────────────────
按 Enter 打断朗读；输入文字后 Enter 可直接提交下一句；滚轮查看历史
────────────────────────────────────────
* 
```

含义：

- 顶部淡蓝色方框显示模型、思考模式和配置文件；它属于消息区内容，会随对话变长一起被顶出画面。
- `*` 表示用户输入，显示为白色。
- `^` 表示 AI 回复，显示为白色；等待模型返回和 AI 输出过程中 `^` 都会闪烁，输出结束后停止。
- `!` 表示系统消息或错误。
- `·` 表示 Agent 工具状态。
- 对话与对话之间保留一行间隔。
- 鼠标滚轮向上查看更早的消息，向下回到底部；新消息到达时自动回到底部。
- 底部输入栏固定显示，用户始终在最底部输入。
- 状态栏显示等待、工具调用、朗读和错误状态。
- 等待模型返回时，消息区会显示闪烁的 `^ AI 正在思考`，状态栏会显示随机颜文字和跳动省略号，例如：

```text
AI 正在思考  (｡･ω･｡)...
```

Agent 工具调用属于次级状态，显示在消息区：

```text
· Agent 第 1 步请求工具：read_file
```

## 技术方案

当前实现使用标准终端能力，而不是 GUI 或真正的字体控制：

- ANSI SGR：灰色、弱显示、重置样式。
- ANSI alternate screen：进入独立全屏缓冲区，退出后恢复原终端内容。
- ANSI 光标控制：固定消息区、状态栏和输入栏。
- ANSI SGR mouse tracking：在支持的终端中接收鼠标滚轮事件，用于滚动消息区。
- 内置 Markdown 子集解析：不新增依赖，将常见 Markdown 转成终端行和 ANSI 样式。
- Unicode 字符：前缀、颜文字、状态文本。
- 后台线程：模型请求阻塞期间刷新等待动画。
- 输出锁：所有动态状态行通过同一个渲染器写入，降低错行概率。
- `msvcrt`：Windows 下读取单字符输入，用于底部输入栏和朗读期间打断。

程序会尝试在 Windows 控制台中开启 Virtual Terminal Processing。终端不支持全屏 TUI 时会自动降级到旧的行内 UI。

## 文件边界

- `fullscreen_tui.py`：全屏 TUI 布局、Markdown 渲染、消息区、状态栏、底部输入栏。
- `terminal_ui.py`：终端样式、ANSI 能力检测、状态行、等待动画。
- `main.py`：业务主流程、语音输入、语音播报、Agent 调用。
- `docs/TERMINAL_UI.md`：本文档，记录交互约定和后续演进方向。

`main.py` 不再直接维护 ANSI 常量和等待动画细节，避免显示逻辑继续散落。

## 限制

- 终端无法真正设置“小字体”，只能使用灰色弱显示模拟次级信息。
- 当前 Agent 请求不是可取消的流式工具循环；等待 AI 网络请求期间会显示状态，但 `Enter` 只用于后续输入和朗读打断，不能强制中断已经发出的网络请求。
- 旧版 Windows 控制台可能不支持 ANSI 或 alternate screen，会自动降级到行内 UI。
- 鼠标滚轮依赖终端支持 SGR mouse tracking；如果终端拦截滚轮或不发送 VT 鼠标事件，程序无法收到滚动输入。
- 标准库 `input()` 不支持 Claude Code 那种多行编辑、历史补全和快捷键体系。
- 当前全屏 TUI 的 Markdown 渲染覆盖常见文本结构，不追求完整 CommonMark 兼容。
- 当前全屏 TUI 的底部输入栏支持输入、退格、Enter 提交，不支持左右移动光标和历史记录。

## 开关

默认会尽量启用全屏 TUI。如果要强制使用旧的行内 UI：

```powershell
$env:AI_DISABLE_FULLSCREEN_TUI = "1"
python main.py
```

## 后续升级

如果要继续向 Claude Code / Codex CLI 靠近，可以分两步：

1. 引入 `rich`：更完整的 Markdown、表格、进度和宽字符处理。
2. 引入 `prompt_toolkit`：更强的输入编辑、历史记录、快捷键、底部状态栏。

这两个依赖会改变安装要求，正式引入前需要先确认。
