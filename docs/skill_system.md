在设计自己的Agent skill系统时，参考成熟的解决方案是一个很好的起点。Claude Code的skill系统就是一个很不错的设计范本。下面我从几个核心机制来为你剖析它的设计，希望能为你带来启发。

### 📂 Skill 存储在哪里？

Claude Code 根据不同作用域，将 Skill 分散存放在多个位置：

*   **个人级**：`~/.claude/skills/`，作用于当前用户的所有项目。
*   **项目级**：`.claude/skills/`（项目根目录），仅作用于当前项目。
*   **插件级**：位于插件自己的 `skills/` 目录下，随插件一起安装和分发。
*   **企业级**：路径由企业IT/管理员配置，作用于整个组织。

**命名与结构**
一个完整的Skill目录通常包含核心的`SKILL.md`文件和可选的辅助资源。目录命名推荐使用 `kebab-case`（例如 `python-code-review`）。典型结构如下：
*   `SKILL.md`：**必需**。核心文件，包含元数据和Markdown格式指令。
*   `scripts/`：可选，放置辅助脚本，如 `lint-check.py`。
*   `references/`：可选，存放参考文档，如官方 `API` 手册。
*   `assets/`：可选，存放模板、图片等资源。

**作用域优先级**
当存在同名Skill时，作用域优先级决定了实际生效的哪个：**项目级 > 个人级 > 企业级**。

### 🧠 AI 如何知道自己有哪些 Skill？

Claude Code 在启动或项目初始化时会进行**发现（Discovery）**。它会遍历上述所有路径，扫描每个Skill目录下的`SKILL.md`文件，并读取文件头部的元数据（`name`和`description`）。但要注意，这时它只会加载这些元数据作为索引，而不会加载`SKILL.md`的完整正文。

### 🎯 AI 如何知道自己要选择哪些 Skill？

这个决策机制的核心是一个基于描述匹配的**自动触发的Prompt注入**过程：

1.  **描述匹配**：当用户发起请求时，AI会检查其内部维护的Skill列表（即`name`和`description`）。AI会根据用户的自然语言输入，判断其意图是否与某个Skill的`description`相匹配。
    *   **描述至关重要**：`description`字段是AI判断是否启用一个Skill的唯一依据。描述必须清晰、准确地说明“技能何时应该被使用”，最好包含具体的触发关键词（如“审查这段代码”、“生成提交信息”、“解释这段代码是如何工作的”），以便AI进行匹配。
2.  **内容注入（Injection）**：一旦匹配成功，AI会临时加载对应Skill的`SKILL.md`文件正文内容，并通过 `--append-system-prompt` 等方式将其注入到当前会话的系统提示词或上下文中。
3.  **执行指令**：AI在接收到这些注入的指令后，会严格遵守并执行其中定义的步骤。

此外，用户也可以**手动调用** `/skill-name` 来强制执行某个Skill。作为设计师，你也可以考虑在系统中增加一个类似的“查看所有Skills”的命令（如`/skills`），这对提升用户的可控性和透明度很有帮助。

### 💡 核心设计理念：Prompt 注入与渐进式披露

Claude Code Skill 的本质是**一套基于 Prompt 注入的元工具架构**。它不是一个可执行的程序，而是一种动态的上下文增强机制。其精妙之处在于**渐进式披露（Progressive Disclosure）**：

*   **轻量级发现**：系统启动时，只加载所有Skill的`name`和`description`，占用极小的上下文窗口。
*   **按需加载**：只有当用户的问题与描述匹配时，才会将一个Skill的完整指令加载到上下文中。

这种方法非常省token，尤其适合你的TUI Agent这类对效率有要求的应用。同时，它也**将知识与AI的行为模型分离**：我们定义的是纯粹的指令，而不是代码，这使得Skill更安全，并且可以被多个AI（如Claude, GPT）以相同方式执行。

### 📜 核心文件：SKILL.md 格式详解

了解了大致流程，再来看`SKILL.md`文件的具体格式。它主要由两部分构成：

*   **YAML 元数据块**：位于文件顶部，被`---`包裹。必须包含 `name` 和 `description` 字段。
*   **Markdown 正文**：元数据之后的部分，用自然语言详细指导AI的行动步骤、输出格式、使用示例等。

为了让你有更直观的感受，这是一个标准的`SKILL.md`文件示例：

```yaml
---
name: python-code-review
description: 对Python代码进行PEP8规范审查、漏洞检测、可读性优化，适用于后端代码提交前校验。
---

# Python 代码审查技能

## 执行目标
严格遵循PEP8规范，检测代码语法漏洞、冗余逻辑、命名不规范问题，输出结构化审查报告。

## 执行步骤
1. 读取待审查Python代码，解析语法结构
2. 校验变量命名、缩进、注释、空行等规范
3. 检测潜在bug（如未捕获异常、内存泄漏）
4. 给出优化建议与修改后的代码片段
5. 生成Markdown格式审查报告

## 输出要求
报告需包含：问题等级（高危/中危/低危）、问题位置、违规规范、优化方案。
```

### 🚀 给 TUI Agent 的设计建议

最后，为你规划自己的Skill系统提供一些参考思路：

*   **架构参考**：Codex 采用 `$HOME/.agents/skills/`，Claude 采用 `~/.claude/skills/`。你的TUI Agent可以遵循 `~/.tui-agent/skills/` 这种常见的`点文件夹`规范。
*   **核心机制**：**Prompt注入**是绝对核心，管理好描述匹配的精确度与上下文窗口的消耗。同时，提供一种显式列出Skills的命令行方式（如`/skills`），会让系统对用户更透明、更可控。
*   **开放性参考**：Agent Skills 是遵循开放标准的（Codex 和 Claude 都基于此）。如果你的TUI Agent也支持该标准，就能复用社区为Claude等工具编写的大量现有Skill包。阅读它们的设计也是你学习社区优秀实践的一种方式。
