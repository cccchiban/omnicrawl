# 终端 UI 设计说明

OmniCrawl 使用基于 Textual 的**全屏终端工作台**。框架统一管理屏幕重绘、滚动、焦点、流式内容和模态确认，避免内联 ANSI 输出与终端历史、光标位置和窗口缩放相互竞争。

## 设计目标

- **终端原生透明工作台**：主界面、菜单和模态面板背景均为透明，思考过程块使用淡蓝色背景，正文继承终端默认前景色，完成、工具、异常和推理状态分别使用终端 ANSI 绿、黄、红和品红；临时运行状态使用弱化正文色，布局保持两行 HUD、无卡片消息流和单行起步、按内容伸缩的输入舱。
- **信息层级明确**：用户输入、AI 思考、AI 输出、工具执行、等待状态和人工确认具有稳定且不同的视觉语义。
- **稳定优先**：所有视图变化通过 Textual 主事件循环完成；后台 Agent 线程只发送事件，不直接写终端。
- **窄屏可读**：启动面板、工具参数、确认内容、预输入和等待状态按真实终端列宽换行，不使用虚构的最小宽度。
- **成熟渲染框架**：依赖 `textual`，安装 `requirements.txt` 后即可运行。

## 视觉与交互约定

```text
PRJ project  ·  MDL deepseek-v4-flash  ·  THK MAX  ·  APR MAN  ·  QUE 0                    v0.1.7
IN 18.6K  OUT 2.4K  CA 7.1K  CTX 18.6K/128K  MCP 0                 正在建立项目内容索引 42%
$ 用户问题
思考过程（点击折叠）
◇ AI 回复内容与 Markdown
R  README.md  |  第 1-120 行  ✓ 成功  120ms
◇ 并行子任务  1/3 完成
├─ ✓ 审查 Agent 变更  explore · 完成 · 00:18
├─ ● 审查全屏 TUI 变更  explore · 运行中 · 00:07
└─ ○ 运行回归测试  verify · 等待中
⠋ 正在调用（跟随最新记录）
› 输入消息或 / 命令
```

| 内容 | 表示方式 | 设计意图 |
| --- | --- | --- |
| 用户输入 | `$` 前缀，低不透明度紫色背景 | 通过符号和模拟透明的紫色背景区分用户内容，同时保留终端原生背景观感。 |
| AI 思考 | 默认展开的“思考过程”，点击标题折叠/展开，使用淡蓝色背景 | 每次模型推理独立成段，不设置展开快捷键；模型不返回 `reasoning_content` 时不显示空段。 |
| AI 输出 | `◇` 前缀 Markdown，无背景 | 流式分片更新同一条受控记录，不移动终端光标；长内容自动换行，消息组件不生成内部横向滚动条；消息区上下贴合遥测与输入框，不额外保留垂直留白。 |
| SubAgent 进度 | 以 `◇` 根节点和 `├─`/`└─` 子节点组成批次进度树 | 同一 `batch_id` 只保留一棵树，同一 `task_id` 原地更新等待、运行、等待审批、完成、失败或取消状态；运行节点显示动态耗时。界面只读取任务类型、描述和安全 ID，不展示 prompt、完整结果或原始异常。 |
| 运行状态 | 消息流中紧跟最新内容的临时单行状态 | 仅任务活动期间轮换 `⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏` Braille 状态帧；相同阶段的流式分片不会重置当前帧，阶段切换时才回到首帧。状态始终原位移动到最新推理、正文或工具记录之后，而非固定在对话框上方；完成后移除，不写入持久对话。 |
| 工具执行 | 默认折叠的工具记录；工作区读取/搜索/目录列表与文件变更使用紧凑操作摘要 | 工作区读取/搜索/目录列表使用 `R path \| 第 N-M 行` / `S path \| 目标` / `L path \| 项数`，例如 `L . \| 12 项  ✓ 成功  1.8s`；Bash 与 PowerShell 分别使用 `B  cmd: pytest  ✓ 成功  1.8s` 和 `P  cmd: pytest  ✓ 成功  1.8s`，不重复显示工具名称；其他命令工具使用 `图标 短名称 \| 参数摘要 状态图标 状态 耗时`。`write_file`：默认展开并显示文件内容预览；`replace_text`：使用低不透明度灰色背景，标题为 `M path \| +N -M`，展开后旁注行号 `+`/`-` 预览；覆盖写无旧内容时显示 `rewrite +N lines`，不编造假 diff。完整内部工具名仅在展开详情中显示。除 `write_file` 外，工具执行中与完成后均默认折叠。 |
| 成功/失败 | 折叠标题文本标记 + 语义色 | 不只依赖颜色表达状态。 |
| 顶部 HUD | 两行灰色竖线分栏稳态：第一行 `PRJ`（固定 16）│ `MDL`（固定 31）│ `THK`（固定 14）│ `APR` │ `MCP` │ `QUE` │ 行尾版本号；第二行固定项目名（居中 16）│ `CTX` 占用（固定 31，百分比 + 进度条 + 用量/总量，内容右对齐）│ `IN` │ `OUT` │ `CA`（固定 10）│ `tok/s`（固定 15）│ 行尾索引构建进度；索引构建期间在行尾显示进度 | 段规则：竖线为纯分隔符（不带空格），空格属于段内填充；第一行 `PRJ`/`MDL`/`THK` 固定段宽左对齐补空格，第二行项目名与索引状态居中，各段固定宽度使两行竖线逐点对齐（cell）：CTX前│==MDL前│(17)、IN前│==MDL尾│(49)、OUT尾│==THK尾│(64)、CA尾│==APR尾│(75)、tok/s尾│==QUE尾│(91)；CTX 段填充置于内容左侧（右对齐），使 `0/1M` 与右侧竖线仅 1 空格间隔。所有分隔竖线与行尾闭合竖线使用灰色（`bright_black`，比 dim 更清晰）；版本号与索引状态被弹性占位推到整行最右端，剩余空间留白在两者与正文之间；索引状态空闲时隐藏整段（含其左侧分隔）避免占位，构建时才显示。固定标签和分隔符使用灰色，动态值使用终端默认前景色；布局高度为 2（1 行内容 + 1 行底边框），避免 Textual `border-bottom` 把内容高度压成 0。隐藏完整项目路径；审批压缩为 `MAN`/`AUTO`/`REV`；长字段截断。首屏后后台读取 PyPI RSS，检查期间行尾版本号循环显示四帧灰白指示器，发现更新时行尾显示 `v当前 ↑ v最新` 并在消息区提示升级命令；检查结果缓存 24 小时，网络失败静默降级。 |
| 输入区 | 单行起步、最多五行的软折行编辑器；Enter 发送，Shift+Enter 换行；输入 `/` 时向上展开命令菜单 | 长输入会按实际软折行自动增长，达到五行后在编辑器内滚动，不显示横向滚动视图；粘贴内容超过五行时，输入框中缩略为 `[粘贴 #编号 +行数 行]`，提交和排队时仍恢复为完整原文；菜单合并内置命令和动态 `/skill:*`，实时过滤且最多显示 8 条；上下键选择，Enter 或 Tab 只填入输入框，不立即执行。生成期间按 Enter 提交的内容进入 FIFO 队列，并显示排队数量。 |
| 人工确认 | 透明模态层、ANSI 蓝色边框与绿色批准操作 | 风险操作保持明确，同时不遮盖终端背景。 |

Token 遥测中的 `IN` 是最近一次模型请求的输入 Token，`OUT` 是输出 Token，`CA` 是缓存命中的输入 Token，`CTX` 使用 `IN / llm.context_window_tokens` 表示当前上下文占用。`tok/s` 位于 `MCP` 之前，是 Agent 流式生成的实时速率：按最近 2 秒滑动窗口内的思考与正文文本增量估算（CJK 字符按 1 token、其他字符按 4 字符 1 token），每 0.5 秒刷新一次；生成期间显示一位小数值，空闲或回合结束时显示 `--` 并清空采样，流回滚重试时同样归零，避免残留旧速率。占用条和百分比随动态数值统一使用终端默认前景色，不以颜色编码阈值。终端自适应令牌统一定义在 `omnicrawl/ui/fullscreen/theme.py`：Textual CSS 使用 `ansi_default`/`ansi_*`，Rich 文本使用 `default` 与标准 ANSI 色名。

主界面首屏显示后会立即在后台发现 MCP 能力；发现期间静默锁定输入，不显示瞬时“等待”状态，避免初始化闪屏和首条消息重复触发能力加载。加载失败仍会显示错误记录，但不会阻止后续使用内置工具。

当 `approval.mode` 为 `manual` 时，受限工具按模型调用顺序逐个显示确认卡；`auto` 与 `review` 按现有策略直接执行或审查。一次模型响应包含多个工具调用时，审批全部完成后，除 `write_file` 和显式删除行为外的工具并行执行；写文件与删除调用作为串行屏障，不与同批其他工具重叠。Host 等待整批结束，即使部分调用失败也继续收集其余结果，最后按模型原始调用顺序统一回传。工具调用记录默认折叠，标题展示工具名、调用状态和耗时，点击后显示参数及执行结果。输入 `/approval:manual`、`/approval:auto`、`/approval:review` 可切换模式。输入 `/settings` 可打开中文设置面板，使用方向键和 Enter/空格修改模型、推理强度、上下文长度、审批模式、记忆、MCP、插件、子任务、上下文压缩、文件名快速索引和内容关键词索引开关；修改会立即应用并写入用户配置目录。`/settings → 工具开关` 进入二级面板，可逐工具启用/关闭内置工具（默认除 PowerShell 关闭外其余全部启用），切换后立即重建 Agent 工具表并保存到 config.yaml 的 `tools` 段；未注册的条件工具会显示“（未注册）”标注。`/settings` 中的模型切换项会打开双列选择器：左列为“渠道选择”，显示已启用渠道并支持上下键循环切换；右列为当前渠道可用模型，只展示该渠道 Profile 的自动发现结果。按 Enter 可切换左列选中的渠道默认模型，或切换右列选中的发现模型；没有独立渠道配置时会从当前模型目录自动补齐渠道。首次启动和运行设置中的“编辑模型渠道”页面，以及 `/settings → MCP → Server → 编辑 MCP Server` 页面，协议、请求方式、传输方式和风险等级等枚举项使用带边框的可点击下拉框；模型渠道编辑器还支持设置可选的 `User-Agent`，留空则使用 SDK 默认值；鼠标点击当前值可展开选项，点击选项后立即显示选中值，键盘上下/Enter 仍保持可用。设置列表在标准终端高度下完整显示，终端较矮时会随当前选中项自动滚动，避免末尾开关被裁掉。上下文压缩开关对应 `context_compaction.enabled`，默认关闭；启用时会先校验当前模型的上下文窗口，并同步注册受当前摘要授权的证据恢复工具，失败时保留旧运行态。关闭 MCP、插件或子任务前会先完成对应资源/任务收尾，失败时同样保留原运行态；开启 SubAgent 会同步重建 Coordinator 和 Host 工具表。关闭设置面板后 HUD 会刷新为最新模型、推理强度和审批模式。

## 稳定性策略

1. **主线程渲染**：Agent 在 Textual worker 线程执行；每个 `delta/status/tool/usage` 事件均经 `call_from_thread` 回到主循环更新组件。
2. **受控流式记录**：连续正文分片合并进当前助手记录；推理分片合并进当前默认展开的思考段。Markdown 由组件重绘，不使用 ANSI 光标左移或手工清行。
3. **子任务原地聚合**：SubAgent 生命周期事件按 `batch_id` 定位树、按 `task_id` 定位节点。重复的 `started`/`running` 事件只更新状态，不追加消息；终态节点拒绝迟到活动事件回退，避免并发回调造成视觉倒序。
4. **模态审批**：受限工具请求以模态框呈现；后台线程等待回调结果，界面状态不会被并发终端输出打散。
5. **可控滚动与焦点**：消息区独立滚动，输入框固定在底部，默认只占一行，并按软折行自动增长至五行且不显示横向滚动视图；Enter 提交，Shift+Enter 插入换行。AI 回复、思考和工具记录支持文本选择或点击折叠，但不进入焦点链。每轮完成后自动恢复输入焦点并继续处理 FIFO 队列。斜杠菜单打开时由输入区接管上下键、Enter 和 Tab，补全后关闭菜单；用户再次按 Enter 才提交命令。
6. **取消与输入语义**：`Esc` 在任务执行中请求取消，在空闲时聚焦输入框；`Ctrl+C` 在输入框有选区时复制，无输入选区但消息区存在鼠标选区时复制 AI 回复，否则清空输入框；任务执行期间按 Enter 的消息和斜杠命令进入 FIFO 队列，当前回合结束或取消后继续发送；`Ctrl+L` 仅清空当前视图，不清空会话数据，`Ctrl+Q` 退出工作台。
7. **终端输入自愈**：窗口失焦、重新聚焦和按下 `Esc` 时统一清理组件捕获、Screen 选区与 Driver 按键状态；周期看门狗还会检测 Windows 锁屏、息屏或终端恢复后被重置的 VT 输入模式，并恢复控制台模式及鼠标、焦点、键盘和括号粘贴协议。若终端漏掉 `MouseUp`，未完成交互连续 3 秒没有变化后会自动复位；已完成的消息文本选区不会被空闲看门狗清除。锁屏恢复或 Driver 停止期间的瞬时读取异常只会跳过当前看门狗周期，不会升级为 Textual 致命退出。全屏应用无论正常还是异常退出，都会在 Driver 停止后直接向真实终端再次关闭鼠标报告模式；独立 PowerShell 宿主还会在 `Read-Host` 前关闭鼠标、焦点、键盘和括号粘贴协议并清空残留输入，防止鼠标移动显示为 SGR 转义字符。Textual 的非零退出码会继续传递给启动器，异常结束不再伪装成正常结束。

## 文件边界

- `omnicrawl/ui/fullscreen/`：Textual 应用、全屏布局、流式事件桥接和人工确认模态框。
  - `__init__.py`：`OmniCrawlApp` 入口、Widget 生命周期与渲染。
  - `turns.py`：Agent 回合生命周期控制器（无 Textual 依赖）。
  - `commands.py`：斜杠命令分派（无 Textual 依赖）。
  - `settings.py`：中文运行设置模态面板与即时保存。
  - `theme.py`：透明终端主题、Textual Theme 注册，以及 CSS/Rich 对应的终端自适应色彩令牌。
  - `monitor.py`：Monitor 游标/轮询状态适配（无 Textual 依赖）。
  - `widgets.py` / `hud.py` / `tool_diff.py`：界面组件、SubAgent 进度树、顶部遥测与文件变更 diff 渲染。
- `main.py`：默认创建 Agent 后直接启动全屏工作台。
- `omnicrawl/ui/tui/`、`stream_turn.py`、`chat_session.py`：保留为兼容输出与既有测试支持，不再作为默认交互入口。
- `tests/test_fullscreen_tui.py`、`tests/test_fullscreen_turns.py`、`tests/test_fullscreen_commands.py`、`tests/test_fullscreen_monitor.py`：全屏工作台与状态边界回归。
- `tests/test_terminal_ui.py`：终端样式、窄屏、Unicode、确认、工具、spinner 和回归测试。
- `tests/test_inline_input.py`：输入编辑、删除键和历史记录测试。
- `omnicrawl/docs/TERMINAL_UI.md`：本文档。

## 兼容范围与限制

- 验收目标为 Windows Terminal、PowerShell 和 VS Code 集成终端。
- 必须安装 `textual`；缺少依赖时执行 `pip install -r requirements.txt`。
- 当前全屏版支持普通对话、流式 Markdown、工具记录、取消、斜杠命令和手动审批；窗口过窄时由 Textual 负责折行和滚动。
- 旧 ANSI 模块仍保留，供测试与非交互输出使用。

## 验证清单

每次修改 TUI 后至少执行：

```powershell
python -m unittest tests.test_fullscreen_tui tests.test_terminal_ui tests.test_inline_input -v
python -m unittest discover -s tests -v
python -m compileall -q omnicrawl main.py
git diff --check
```

手工冒烟时覆盖普通输入、长/CJK/emoji 输入、流式 Markdown、工具成功/失败、人工确认、错误、`Esc` 取消、`Ctrl+C` 复制/清空和生成期间多条消息 FIFO 排队路径；再检查窗口缩放后的 HUD、消息滚动和固定输入框。
