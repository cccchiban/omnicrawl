# 终端 UI 设计说明

OmniCrawl 使用基于 Textual 的**全屏终端工作台**。框架统一管理屏幕重绘、滚动、焦点、流式内容和模态确认，避免内联 ANSI 输出与终端历史、光标位置和窗口缩放相互竞争。

## 设计目标

- **终端原生透明工作台**：主界面、菜单和模态面板背景均为透明，思考过程块以 Markdown 渲染并统一为灰色前景 + 代码块同款灰色背景（Maple Mono 等宽字体由终端提供），完成、工具、异常和推理状态分别使用终端 ANSI 绿、黄、红和品红；临时运行状态使用弱化正文色，布局保持两行 HUD、无卡片消息流和单行起步、按内容伸缩的输入舱。
- **信息层级明确**：用户输入、AI 思考、AI 输出、工具执行、等待状态和人工确认具有稳定且不同的视觉语义。
- **稳定优先**：所有视图变化通过 Textual 主事件循环完成；后台 Agent 线程只发送事件，不直接写终端。
- **窄屏可读**：启动面板、工具参数、确认内容、预输入和等待状态按真实终端列宽换行，不使用虚构的最小宽度。
- **成熟渲染框架**：依赖 `textual`，安装 `requirements.txt` 后即可运行。

## 视觉与交互约定

```text
│ omnicrawl    │ deepseek-v4-flash           │ THK MAX  APR AUTO  MCP 1  QUE 0 │ v0.1.9
│   omnicrawl    │ 0% ░░░░░░░░░░ 0/1M │ IN 18.6K  OUT 2.4K  CA 7.1K   │ tok/s --
$ 用户问题
正在分析用户问题与项目结构……
◇ AI 回复内容与 Markdown
R  README.md  |  第 1-120 行  ✓ 成功  120ms
◇ 并行子任务  1/3 完成
├─ ✓ 审查 Agent 变更  explore · 完成 · 00:18
├─ ● 审查全屏 TUI 变更  explore · 运行中 · 00:07
└─ ○ 运行回归测试  verify · 等待中
⠋ 正在调用（跟随最新记录）
› 输入消息或 / 命令
```

| 输入区 | 单行起步、最多五行的软折行编辑器；Enter 发送，Shift+Enter 换行；输入 `/` 时向上展开命令菜单 | 长输入会按实际软折行自动增长，达到五行后在编辑器内滚动，不显示横向滚动视图；粘贴内容超过五行时，输入框中缩略为 `[粘贴 #编号 +行数 行]`，提交和排队时仍恢复为完整原文；Windows 原始输入模式下（禁用 VT 输入，无法使用 bracketed paste），输入监视器把多行按键流与系统剪贴板比对，完整匹配时转为一次粘贴事件；超过单批 1024 条 Windows 输入记录的大文本按剪贴板前缀暂存，首个换行前使用短等待窗口，停止到码后自动回退为普通输入；菜单合并内置命令和动态 `/skill:*`，实时过滤且最多显示 8 条；上下键选择，Enter 或 Tab 只填入输入框，不立即执行。生成期间按 Enter 提交的内容进入 FIFO 队列，并显示排队数量。输入框按上键/下键可回看本会话已发送的普通消息（进入浏览前的内容自动保存为草稿，下键翻到最新一条后再按一次即恢复原草稿），没有历史时上下键回退为滚动消息区。 |
| 人工确认 | 透明模态层、ANSI 蓝色边框与绿色批准操作 | 风险操作保持明确，同时不遮盖终端背景。 |

OpenAI GPT 的 Chat Completions 与 Responses Runtime 都从稳定的系统提示、项目规范、Skill 和工具 schema 身份生成 `prompt_cache_key`；当前网关若不接受该参数，会自动去掉后重试一次。`CA` 来自 Provider 返回的缓存输入 Token，是 `IN` 的子集，不应与 `IN` 相加；顶部 `CH%` 即缓存率 = `CA ÷ IN`（缓存命中输入占本次总输入的比例），与上下文窗口大小无关。

Token 遥测中的 `IN` 是最近一次模型请求的输入 Token，`OUT` 是输出 Token，`CA` 是缓存命中的输入 Token，`CTX` 使用 `IN / llm.context_window_tokens` 表示当前上下文占用。`CH%` 为缓存率（`CA / IN`，无输入时为 0，异常数据封顶 100%）。`tok/s` 位于 `MCP` 之前，是会话累计的统计平均速率：总输出 Token ÷ 总输出时长，token 来自流式思考与正文增量的字符估算（CJK 字符按 1 token、其他字符按 4 字符 1 token），时长只累计相邻增量间隔内的连续输出，间隔超过 2 秒视为待机（工具执行、模型停顿、回合间隙）不计时，因此数值反映实际平均输出速度而非瞬时值；每 0.5 秒刷新一次，生成期间显示一位小数值，输出停止或回合结束后平均值保留不归零，尚无任何输出记录时显示 `--`；模型流中断回滚重试时会撤销本次回合已累计的量后重新计算。占用条和百分比随动态数值统一使用终端默认前景色，不以颜色编码阈值。终端自适应令牌统一定义在 `omnicrawl/ui/fullscreen/theme.py`：Textual CSS 使用 `ansi_default`/`ansi_*`，Rich 文本使用 `default` 与标准 ANSI 色名。

主界面首屏显示后会立即在后台发现 MCP 能力；发现期间静默锁定输入，不显示瞬时“等待”状态，避免初始化闪屏和首条消息重复触发能力加载。加载失败仍会显示错误记录，但不会阻止后续使用内置工具。

当 `approval.mode` 为 `manual` 时，受限工具按模型调用顺序逐个显示确认卡；`auto` 与 `review` 按现有策略直接执行或审查。一次模型响应包含多个工具调用时，审批全部完成后，所有工具立即并发执行，不再按工具类型建立串行屏障。每个工具在自身真实完成时立即更新 UI 的独立耗时；Host 仍按模型原始调用顺序整理观察结果回传，即使部分调用失败也继续收集其余结果。工具调用记录始终展开，标题展示工具名、调用状态和耗时，除 `write_file`、`replace_text`、`read` 外正文直接显示原始输出（限五行，中间直接折叠不显示任何提示行）；`read` 的正文隐藏；工具调用与输出整卡不使用背景色（终端原生透明背景）、输出为灰色字体。输入 `/approval:manual`、`/approval:auto`、`/approval:review` 可切换模式。输入 `/settings` 可打开中文设置面板，使用方向键移动选中行、Enter/空格确认或切换、Esc 返回上一级，可修改模型、推理强度、上下文长度、审批模式、记忆、MCP、插件、子任务、上下文压缩开关和上下文压缩阈值（按百分比，5% 步进）；修改会立即应用并写入用户配置目录。`/settings → 工具开关` 进入二级面板，可逐工具启用/关闭内置工具（默认除 PowerShell 关闭外其余全部启用），切换后立即重建 Agent 工具表并保存到 config.toml 的 `tools` 段；未注册的条件工具会显示“（未注册）”标注。`/settings` 中的模型切换项会打开双列选择器：左列为“渠道选择”，显示已启用渠道并支持上下键循环切换；右列为当前渠道可用模型，只展示该渠道 Profile 的自动发现结果。按 Enter 可切换左列选中的渠道默认模型，或切换右列选中的发现模型；没有独立渠道配置时会从当前模型目录自动补齐渠道。首次启动和运行设置中的“编辑模型渠道”页面，以及 `/settings → MCP → Server → 编辑 MCP Server` 页面，协议、请求方式、传输方式和风险等级等枚举项使用带边框的下拉框；模型渠道编辑器还支持设置可选的 `User-Agent`，留空则使用 SDK 默认值；这些枚举项不响应鼠标，统一通过键盘操作：Enter 展开选项、上下键选择、Enter 确认、Esc 收起。设置列表在标准终端高度下完整显示，终端较矮时会随当前选中项自动滚动，避免末尾开关被裁掉。上下文压缩开关对应 `context_compaction.enabled`，默认关闭；启用时会先校验当前模型的上下文窗口，并同步注册受当前摘要授权的证据恢复工具，失败时保留旧运行态。上下文压缩阈值按当前模型上下文窗口的百分比换算为 `trigger_context_tokens`（上下文 × 百分比），5% 为一个单位递进；单独修改上下文长度时，阈值会按当前百分比自动重算并同步保存。关闭 MCP、插件或子任务前会先完成对应资源/任务收尾，失败时同样保留原运行态；开启 SubAgent 会同步重建 Coordinator 和 Host 工具表。关闭设置面板后 HUD 会刷新为最新模型、推理强度和审批模式。

## 稳定性策略

1. **主线程渲染**：Agent 在 Textual worker 线程执行；每个 `delta/status/tool/usage` 事件均经 `call_from_thread` 回到主循环更新组件。
2. **受控流式记录**：连续正文分片合并进当前助手记录；推理分片合并进当前默认展开的思考段。Markdown 由组件重绘，不使用 ANSI 光标左移或手工清行。
3. **子任务原地聚合**：SubAgent 生命周期事件按 `batch_id` 定位树、按 `task_id` 定位节点。重复的 `started`/`running` 事件只更新状态，不追加消息；终态节点拒绝迟到活动事件回退，避免并发回调造成视觉倒序。
4. **模态审批**：受限工具请求以模态框呈现；后台线程等待回调结果，界面状态不会被并发终端输出打散。
5. **可控滚动与焦点**：消息区独立滚动，输入框固定在底部，默认只占一行，并按软折行自动增长至五行且不显示横向滚动视图；鼠标滚轮每刻度滚动 5 行，滚动条支持左键按住拖动；输入框保持焦点时 `Up`/`Down` 优先回看本会话已发送的消息（进入浏览前的内容保存为草稿，下键翻到最新一条后再按一次即恢复），没有历史时回退为滚动消息区，`PageUp`/`PageDown` 始终滚动消息区，输入框仍负责文本编辑；Enter 提交，Shift+Enter 插入换行。AI 回复和思考记录不进入焦点链；思考记录与工具记录均始终展开、不响应点击。每轮完成后自动恢复输入焦点并继续处理 FIFO 队列。斜杠菜单打开时由输入区接管上下键、Enter 和 Tab，补全后关闭菜单；用户再次按 Enter 才提交命令。
6. **取消与输入语义**：`Esc` 在任务执行中会立即取消当前回合：主动关闭当前回合的模型响应流、终止正在运行的外部命令进程树、撤销当前同步 SubAgent 批次和待决审批；无法安全强杀的普通 Python 工具线程会在自身取消检查点收尾，其结果不会继续进入父回合。空闲时 `Esc` 聚焦输入框；`/quit` 可在生成期间直接退出当前 TUI，不等待模型或工具自然结束，也不关闭宿主窗口。`Ctrl+C` 在输入框有选区时复制，无输入选区但消息区存在鼠标选区时复制 AI 回复，否则清空输入框；任务执行期间按 Enter 的普通消息进入 FIFO 队列，`/quit` 除外；当前回合结束或取消后继续发送；`Ctrl+L` 仅清空当前视图，不清空会话数据，`Ctrl+Q` 退出工作台。
7. **终端输入自愈**：窗口失焦、重新聚焦和按下 `Esc` 时统一清理组件捕获、Screen 选区与 Driver 按键状态。周期看门狗会检测 Windows 锁屏、息屏或终端恢复后被重置的原始控制台输入模式，并恢复控制台模式及鼠标、焦点、键盘和括号粘贴协议；控制台输入模式启用 `ENABLE_MOUSE_INPUT`，事件监视器通过 `ReadConsoleInputW` 将按键、鼠标按钮、滚轮、窗口尺寸和焦点记录转换为 Textual 事件。锁屏恢复或 Driver 停止期间的瞬时读取异常只会跳过当前看门狗周期，不会升级为 Textual 致命退出。全屏应用无论正常还是异常退出，都会在 Driver 停止后直接向真实终端再次关闭鼠标报告模式；独立 PowerShell 宿主还会在退出前关闭鼠标、焦点、键盘和括号粘贴协议并清空残留输入，防止残留协议影响宿主。Textual 的非零退出码会继续传递给启动器，异常结束不再伪装成正常结束。

## 文件边界

- `omnicrawl/ui/fullscreen/`：Textual 应用、全屏布局、流式事件桥接和人工确认模态框。
  - `__init__.py`：`OmniCrawlApp` 入口、Widget 生命周期与渲染。
  - `turns.py`：Agent 回合生命周期控制器（无 Textual 依赖）。
  - `commands.py`：斜杠命令分派（无 Textual 依赖）。
  - `settings.py`：中文运行设置模态面板与即时保存。
  - `theme.py`：透明终端主题、Textual Theme 注册，以及 CSS/Rich 对应的终端自适应色彩令牌。
  - `monitor.py`：Monitor 游标/轮询状态适配（无 Textual 依赖）。
  - `widgets.py` / `hud.py` / `tool_diff.py`：界面组件、SubAgent 进度树、顶部遥测与文件变更 diff 渲染。
- `main.py`：默认创建 Agent 后直接启动全屏工作台。
- `omnicrawl/ui/tui/`、`stream_turn.py`、`chat_session.py`、`inline_input.py`：旧纯 Python ANSI TUI 已删除，不再提供；纯文本兼容导出仅保留 `omnicrawl.ui.UIStartupError`。
- `tests/test_fullscreen_tui.py`、`tests/test_fullscreen_turns.py`、`tests/test_fullscreen_commands.py`、`tests/test_fullscreen_monitor.py`：全屏工作台与状态边界回归。
- `omnicrawl/docs/TERMINAL_UI.md`：本文档。

## 兼容范围与限制

- 验收目标为 Windows Terminal、PowerShell 和 VS Code 集成终端。
- 必须安装 `textual`；缺少依赖时执行 `pip install -r requirements.txt`。
- 当前全屏版支持普通对话、流式 Markdown、工具记录、当前回合即时取消、`/quit` 斜杠命令和手动审批；窗口过窄时由 Textual 负责折行和滚动。
- 旧纯 Python ANSI TUI 已随 0.1.11 删除；启动路径仅为 Textual 全屏工作台。
